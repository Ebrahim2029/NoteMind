

# User Story Scenario (Table View)

| User Action        | System Steps                                                                                                                                                                                                                                                                                                                | Operational Policy Satisfied                                                                                                       |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Save a note**    | 1. FastAPI writes note to Postgres (version=1).<br>2. Outbox entry created in same transaction.<br>3. Worker consumes Redis job → chunks + embeds → upserts into Chroma.<br>4. Redis invalidates related caches (`search:*`, `note:<id>`).                                                                                  | **Sync latency ≤500ms** (Policy 1).<br>**Cache TTL = 15 mins** ensures fresh retrieval (Policy 2).                                 |
| **Update a note**  | 1. Postgres increments version and updates note.<br>2. Outbox job shipped.<br>3. Worker replaces old Chroma embeddings with latest (is\_latest=true).<br>4. Redis invalidates caches for this note and related searches.                                                                                                    | **Sync latency ≤500ms** (Policy 1).<br>**Cache TTL = 15 mins** (Policy 2).<br>Ensures updated content appears in queries quickly.  |
| **Delete a note**  | 1. Postgres deletes note.<br>2. Outbox job (op=DELETE) added.<br>3. Worker deletes embeddings from Chroma.<br>4. Redis clears note and search caches.                                                                                                                                                                       | **Sync latency ≤500ms** (Policy 1).<br>Ensures deleted notes never appear in retrieval results.                                    |
| **Ask a question** | 1. API checks Redis search cache.<br>2. On miss: embed query → prefilter Postgres → vector search Chroma.<br>3. Results re-ranked using **weights**: Semantic 70%, Last Accessed 20%, Recency 10%.<br>4. Hydrate chunks from Redis/PG; cache results for 15 mins.<br>5. Context packed and sent to OpenAI for final answer. | **Cache-first retrieval** (Policy 2).<br>**Weighted scoring** (Policy 3).<br>**End-to-end RAG latency ≤500ms** (excluding OpenAI). |
